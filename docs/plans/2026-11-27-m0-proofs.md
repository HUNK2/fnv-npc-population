# M0: Proofs, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (native, chosen in the build
> workflow). Steps use checkbox (`- [ ]`) syntax.

**Goal:** answer, in the running game, every "needs a live test" row of the design, so M1 is built
on facts and not hopes.

**Architecture:** one throwaway plugin, `CCProofs.esp`, built from `mod/proofs/proofs.spec.json`
with fnv-mcp's builder; scenario tests in `tests/m0/*.yaml` run with `fnv_test`; results and
evidence in `docs/evidence/m0/`; a Python reference model of the ledger in `tools/ledger_model.py`.

**Tech stack:** fnv-mcp (`fnv_spec`, `fnv_scripts_compile`, `fnv_install`, `fnv_test`, `fnv_func`),
xNVSE, JIP LN NVSE, JohnnyGuitar NVSE 5.28, Python 3.11 (unittest).

**Spec:** the design doc (https://claude.ai/artifact/C2FeS7JVVZXkTiDsAuQKLr), sections "How it is
built in FNV" and "Numbers"; the build workflow `docs/plans/2026-11-26-build-workflow.md`.

## Findings that shape M0 (from the code, 2026-11-27)

- `ComputersMenu::DoClick` (0x00757F70) runs `TERMINAL_MENU_ITEM::RunResultScript` (0x00501830)
  for the clicked row, then shows its submenu or note. So per-row result scripts work in the engine.
- fnv-mcp's builder writes terminal rows **without** result scripts ("a menu item's script is left
  empty"). Dialogue result scripts are supported (compiled in game, cached), so the pattern exists.
- Two ways to know which row was clicked: **(A)** row result scripts (needs the builder extended)
  or **(B)** JIP `SetOnMenuClickEventHandler` on menu 1057 (hooks the menu's click at vtable+0xC)
  and read the clicked tile. Task 0.5 decides with a live test; (B) needs no tool change.
